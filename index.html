Shortest-Path Routing with Dijkstra's Algorithm

Analysis of Algorithms

Priority-queue implementation for a delivery-routing scenario, stress-tested against three edge cases and benchmarked at 10/50/100-node scale.

Implemented Dijkstra's single-source shortest-path algorithm using a binary heap (Python's heapq) for a navigation scenario: routing a delivery vehicle from a warehouse to multiple destinations across a road network, where edge weights represent travel time.

Core implementation

import heapq

def dijkstra(graph, source):
    if not graph:
        return {}

    nodes = set(graph.keys())
    for node in graph:
        for neighbor, _ in graph[node]:
            nodes.add(neighbor)

    distances = {node: float('inf') for node in nodes}
    distances[source] = 0
    priority_queue = [(0, source)]

    while priority_queue:
        current_distance, current_node = heapq.heappop(priority_queue)
        if current_distance > distances[current_node]:
            continue
        for neighbor, weight in graph.get(current_node, []):
            new_distance = current_distance + weight
            if new_distance < distances[neighbor]:
                distances[neighbor] = new_distance
                heapq.heappush(priority_queue, (new_distance, neighbor))
    return distances

Edge-case testing

Verified correctness against three edge cases beyond the happy path: an empty graph (returns immediately with no error), a disconnected graph (unreachable nodes correctly keep distance = infinity), and a graph containing a cycle (the algorithm terminates correctly since stale queue entries are skipped).

Complexity & benchmarking

Compared a naive O(V²) array-scan approach against the O((V + E) log V) binary-heap approach, then benchmarked actual execution time on randomly generated graphs:

10 nodes: 0.0099 ms  ·  50 nodes: 0.0561 ms  ·  100 nodes: 0.1129 ms

Growth was gradual rather than steep, consistent with the theoretical O((V+E) log V) bound — confirming the heap-based approach scales well for real-time route planning in small-to-medium road networks.

Sales Route Optimization via Held–Karp Dynamic Programming

Analysis of Algorithms

Exact Traveling Salesperson solver using bitmask DP, compared empirically against brute-force factorial growth.

Solved the Traveling Salesperson Problem for a nationwide sales team routing scenario using the Held–Karp dynamic programming algorithm, which finds the exact minimum-cost route by decomposing the problem into overlapping subproblems over bitmasked subsets of visited cities.

Recurrence

C(S, i) = min over j in S, j != i of ( C(S \ {i}, j) + cost(j, i) )
Base case: C({1, i}, i) = cost(1, i) for all i != 1

Implementation

def solve_tsp_dynamic_programming(distance_matrix):
    n = len(distance_matrix)
    if n <= 1:
        return distance_matrix[0][0] if n else 0

    num_states = 1 << n
    memo = [[float('inf')] * n for _ in range(num_states)]

    for i in range(1, n):
        memo[(1 << 0) | (1 << i)][i] = distance_matrix[0][i]

    for subset_size in range(3, n + 1):
        for mask in range(num_states):
            if not (mask & 1) or bin(mask).count('1') != subset_size:
                continue
            for i in range(1, n):
                if not (mask & (1 << i)):
                    continue
                prev_mask = mask ^ (1 << i)
                min_dist = float('inf')
                for j in range(1, n):
                    if j == i or not (prev_mask & (1 << j)):
                        continue
                    cost = memo[prev_mask][j] + distance_matrix[j][i]
                    min_dist = min(min_dist, cost)
                memo[mask][i] = min_dist

    full_mask = (1 << n) - 1
    return min(memo[full_mask][i] + distance_matrix[i][0] for i in range(1, n))

Brute-force vs. dynamic programming

Brute-force permutation search runs in O(n!) time; Held–Karp runs in O(n²·2ⁿ). At 15 cities, brute force must check over 14 billion complete tours — at 100,000 checks/second, nearly 40 hours. The DP approach checks roughly 7.3 million state transitions instead, finishing in a fraction of a second.

Trade-off: DP guarantees the global optimum and avoids factorial blow-up, but its O(n·2ⁿ) memory table becomes the practical bottleneck past ~25 cities.

HTTP & TCP Traffic Analysis with Wireshark

Advanced Networking and Data Security

Packet-level capture and analysis identifying the TCP handshake, client OS fingerprint, and network hardware vendors from raw traffic.

Acting as a network engineer analyzing a client's traffic, captured a live HTTP session in Wireshark and worked backward from the raw packets to reconstruct connection details that aren't visible from a browser alone.

What the capture revealed

  • The TCP 3-way handshake (SYN → SYN-ACK → ACK) establishing the connection
  • The local host's IP (192.168.1.164) and its network interface vendor (Apple) from the Ethernet frame
  • The gateway device's hardware vendor (Vantiva) from its MAC address
  • Client OS platform (macOS) and browser language (en-US), both readable from HTTP request headers
Even a single page load exposes a surprising amount of client-side metadata purely from packet headers — a good practical illustration of why header hygiene matters for privacy-conscious services.

iOS BMI Calculator — SwiftUI + OOP

Mobile Application Development

A working SwiftUI app separating business logic from UI, alongside a written comparison of Swift structs vs. classes.

Built a small iOS app in SwiftUI that calculates BMI from user-entered age, weight, and height, cleanly separating the calculation logic (a plain Swift class) from the presentation layer (a SwiftUI view) — an explicit exercise in object-oriented separation of concerns.

Business logic layer

class BMICalculator {
    var age: Int
    var gender: String
    var weight: Double // kg
    var height: Double // meters

    func calculateBMIValue() -> Double {
        guard height > 0 else { return 0.0 }
        return weight / (height * height)
    }

    func determineCategory(bmi: Double) -> BMICategory {
        if bmi < 18.5 { return .underweight }
        else if bmi < 24.9 { return .normal }
        else { return .overweight }
    }
}

Also covered in the same assignment: a comparison of Swift structs (value types, copied on assignment, no inheritance) vs. classes (reference types, shared instances, support inheritance) — illustrated with a side-by-side code example showing how mutating a copied struct leaves the original untouched, while mutating a class instance affects every reference to it.

Automated Daily Report Download & Scheduling

Operating Systems 2

A Bash script that downloads, timestamps, and organizes a daily report file, documented for scheduling via cron or Windows Task Scheduler.

Wrote a Bash script to automate a recurring e-commerce operations task: downloading a daily sales report, saving it with a date-stamped filename to avoid overwrites, and verifying the download succeeded — then documented how to schedule it to run unattended.

#!/bin/bash
REPORT_URL="https://example.com/Sample-Spreadsheet-1000-rows.csv"
DESTINATION_FOLDER="$HOME/SalesReports"
FILENAME="Sample-Spreadsheet-$(date +%Y-%m-%d).csv"

mkdir -p "$DESTINATION_FOLDER"

wget -O "$DESTINATION_FOLDER/$FILENAME" "$REPORT_URL"

if [ -f "$DESTINATION_FOLDER/$FILENAME" ]; then
    echo "Report downloaded successfully to $DESTINATION_FOLDER/$FILENAME"
else
    echo "Download failed. Please check the URL or internet connection."
    exit 1
fi

Documented scheduling via crontab -e on macOS/Linux (0 8 * * * /bin/bash /path/to/script.sh for a daily 8am run) and via Windows Task Scheduler as a cross-platform alternative.
